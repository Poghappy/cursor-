## 🔄 任务流转规则

### 1. Backlog → Ready

**条件**:

- [ ] 所有依赖任务已完成
- [ ] 资源已分配确认
- [ ] 需求已完全明确
- [ ] 开始日期已到
- [ ] 负责人已确认接受

**操作**: BA或PM移动任务

### 2. Ready → In Progress

**条件**:

- [ ] 负责人开始工作
- [ ] WIP限制未超过（≤5）
- [ ] 资源可用

**操作**: 负责人移动任务并更新状态

### 3. In Progress → In Review

**条件**:

- [ ] 开发工作完成
- [ ] 自测通过
- [ ] 代码提交
- [ ] 准备好被审阅

**操作**: 负责人移动并分配审阅人

### 4. In Review → Done

**条件**:

- [ ] 所有验收标准达成（参考`ACCEPTANCE_CRITERIA.md`）
- [ ] 代码审阅通过
- [ ] 测试通过
- [ ] 文档更新

**操作**: 审阅人确认后移动

### 5. 任意状态 → Blocked

**条件**:

- 遇到无法自行解决的阻塞
- 依赖外部资源未就绪
- 发现严重技术问题

**操作**: 负责人标记并说明阻塞原因，通知PM

## 📅 每日更新流程

### 每日站会后更新 (9:15-9:30)

**BA负责更新**:

1. **移动任务状态**
   - 根据站会信息更新任务位置
   - 标记新的In Progress任务
   - 移动完成的任务到Done
2. **更新统计**
   - 更新各状态任务数量
   - 计算完成率
   - 更新里程碑进度

3. **识别风险**
   - 标记阻塞任务
   - 记录阻塞原因
   - 通知PM协调解决

4. **同步看板**
   - 提交看板更新到Git
   - 通知团队查看
   - 在项目频道发布快照
