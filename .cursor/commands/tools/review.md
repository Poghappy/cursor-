# 代码审查 (Code Review)

**工具目标**: 对代码进行全面的质量审查。

## 审查维度

### 1. 代码规范

- [ ] 遵循 TypeScript 严格模式
- [ ] 遵循 ESLint 配置
- [ ] 代码格式符合 Prettier 规范
- [ ] 命名清晰有意义

### 2. 代码质量

- [ ] 函数职责单一
- [ ] 避免代码重复
- [ ] 复杂度控制合理
- [ ] 注释清晰准确

### 3. 架构设计

- [ ] 业务逻辑在 `src/services/`
- [ ] 控制器仅做路由和校验
- [ ] 依赖注入和接口抽象
- [ ] 模块耦合度低

### 4. 错误处理

- [ ] 统一错误响应格式
- [ ] 异常情况处理完善
- [ ] 输入验证充分
- [ ] 日志记录完整

### 5. 测试覆盖

- [ ] 单元测试覆盖核心逻辑
- [ ] 集成测试覆盖关键流程
- [ ] 测试用例质量高
- [ ] 测试覆盖率 > 80%

### 6. 安全性

- [ ] 无 SQL 注入风险
- [ ] 无 XSS 漏洞
- [ ] 敏感数据加密
- [ ] 权限验证完善

### 7. 性能

- [ ] 数据库查询优化
- [ ] 避免 N+1 查询
- [ ] 合理使用缓存
- [ ] 避免内存泄漏

## 审查流程

1. **自动检查**

   ```bash
   npm run lint        # ESLint 检查
   npm test           # 测试执行
   npm run test:coverage  # 覆盖率检查
   ```

2. **人工审查**
   - 阅读代码逻辑
   - 检查设计模式
   - 验证错误处理
   - 评估性能影响

3. **输出反馈**
   - 标识问题代码位置
   - 说明问题原因
   - 提供改进建议
   - 给出示例代码（如需要）

## 审查报告模板

```markdown
## 代码审查报告

### 审查范围

- 文件1
- 文件2

### 发现问题

#### 严重问题

- [ ] 问题描述（位置：file:line）

#### 一般问题

- [ ] 问题描述（位置：file:line）

#### 建议改进

- [ ] 改进建议

### 审查结果

- [ ] 通过
- [ ] 需要修改后通过
- [ ] 不通过
```

## 常见问题

1. **业务逻辑在控制器** → 移到 service 层
2. **缺少错误处理** → 添加 try-catch 和统一错误响应
3. **缺少输入验证** → 使用 Joi 等验证库
4. **测试覆盖不足** → 补充测试用例
5. **代码重复** → 提取公共函数
