# 生成产品需求文档 (PRD)

**阶段目标**: 基于用户故事生成完整的产品需求文档。

## 输入来源

- **用户故事**: `docs/USER_STORIES.md`
- **项目背景**: `docs/PROJECT_BRIEF.md`（如果有）

## 输出要求

### 1. 产品概述

- 产品愿景和目标
- 非目标（Out of Scope）
- 目标用户画像

### 2. 功能需求（MoSCoW 优先级）

- **Must Have**: 必须有
- **Should Have**: 应该有
- **Could Have**: 可以有
- **Won't Have**: 暂不实现

### 3. 主要业务流程

使用 Mermaid 流程图描述关键流程

### 4. 功能详细说明

每个功能包含：

- 详细描述
- 用户场景和操作步骤
- 验收标准

### 5. 接口与数据契约

- API 接口设计（RESTful 规范）
- 数据模型定义（TypeScript 接口）
- 错误处理策略
- 重试和超时设置

### 6. 非功能需求

- 性能：响应时间、吞吐量、并发数
- 安全：认证、授权、加密
- 可用性：系统可用性、故障恢复
- 可观测性：监控、日志、告警

### 7. 验收标准矩阵

用户故事与测试用例的映射表

### 8. 风险评估和发布计划

## 输出文件

生成 `docs/PRD.md`，包含上述所有内容。

## 质量检查

- [ ] 产品愿景清晰，目标可衡量
- [ ] 功能需求完整，优先级合理
- [ ] API 设计规范，数据模型完整
- [ ] 非功能需求具体可测量

## 下一步

完成后使用 `/handover` 生成交接 JSON，交接给 **BA** 或 **Arch** 角色。
