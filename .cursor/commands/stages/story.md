# 生成用户故事 (User Story)

**阶段目标**: 基于输入生成高质量的用户故事与 Gherkin 验收标准。

## 输入信息

请提供以下信息（或从项目中提取）：

- **项目名**: {PROJECT_NAME}
- **目标用户**: {AUDIENCES}
- **业务目标**: {GOAL}
- **约束条件**: {CONSTRAINTS}
- **截止时间**: {DEADLINE}

## 输出要求

### 1. 用户故事（至少 3 条）

每条故事包含：

- **作为** [用户角色]
- **我想** [功能描述]
- **以便** [业务价值]

按优先级分类：

- **Must Have**: 核心功能，必须实现
- **Should Have**: 重要但非核心
- **Could Have**: 边界条件和特殊场景

### 2. Gherkin 验收标准

```gherkin
Given [前置条件]
When [用户操作]
Then [预期结果]
And [附加验证]
```

### 3. 非功能需求

- 性能要求（响应时间、并发数）
- 安全要求（加密、访问控制）
- 可用性要求（系统可用性）
- 可观测性要求（监控、日志）

### 4. 风险与假设

- 技术风险、业务风险、时间风险
- 技术假设、业务假设、用户假设

## 输出文件

生成 `docs/USER_STORIES.md`，包含上述所有内容。

## 质量检查

- [ ] 每条故事有明确的用户角色和业务价值
- [ ] 验收标准可测试可验证
- [ ] 非功能需求具体可测量
- [ ] 风险识别全面
