# 迭代优化阶段 (Iteration)

**阶段目标**: 基于测试反馈和用户需求进行系统优化和功能迭代。

## 输入来源

- **测试报告**: `docs/TEST_REPORT.md`
- **用户反馈**: 用户使用反馈和建议
- **性能数据**: 系统监控和性能指标
- **缺陷列表**: Bug 跟踪系统的缺陷清单

## 输出要求

### 1. 问题分析

- **问题分类**: 功能缺陷、性能问题、体验问题
- **优先级排序**: P0/P1/P2 级别划分
- **影响范围**: 受影响的用户和功能
- **根因分析**: 问题的根本原因

### 2. 优化方案

```markdown
### 问题ID: P0-001

**问题描述**: 用户登录响应缓慢

**根因分析**:

- 数据库查询未使用索引
- 缓存未命中导致重复查询

**优化方案**:

1. 为 email 字段添加索引
2. 实现用户信息 Redis 缓存
3. 优化查询语句

**预期效果**:

- 响应时间从 3s 降低到 500ms
- 数据库负载降低 60%
```

### 3. 功能改进

- **新增功能**: 用户反馈的新需求
- **功能优化**: 现有功能的改进
- **交互优化**: 用户体验提升
- **性能优化**: 系统性能改进

### 4. 技术债务清理

- **代码重构**: 改进代码结构和质量
- **依赖更新**: 更新过时的依赖包
- **测试补充**: 补充缺失的测试用例
- **文档更新**: 更新过时的文档

### 5. 实施计划

| 任务ID | 任务名称       | 优先级 | 工期 | 负责人 | 状态   |
| ------ | -------------- | ------ | ---- | ------ | ------ |
| IT-001 | 数据库索引优化 | P0     | 1天  | Dev    | 进行中 |
| IT-002 | 缓存机制实现   | P0     | 2天  | Dev    | 待开始 |
| IT-003 | UI交互优化     | P1     | 3天  | Dev    | 待开始 |

### 6. 验证测试

- **回归测试**: 验证修复未引入新问题
- **性能测试**: 验证性能优化效果
- **用户验收**: 用户确认优化效果
- **监控跟踪**: 持续监控系统指标

## 迭代流程

### 第一步: 问题收集与分析

1. 收集测试报告和用户反馈
2. 整理和分类问题清单
3. 进行优先级排序
4. 分析问题根本原因

### 第二步: 制定优化方案

1. 设计技术解决方案
2. 评估实施难度和风险
3. 制定详细实施计划
4. 分配任务和资源

### 第三步: 实施优化

1. 按计划执行优化任务
2. 进行代码审查
3. 编写和运行测试
4. 进行性能验证

### 第四步: 验证发布

1. 进行回归测试
2. 用户验收测试
3. 准备发布计划
4. 监控系统运行

## 质量检查

- [ ] 问题分析全面准确
- [ ] 优化方案可行有效
- [ ] 实施计划合理可行
- [ ] 测试覆盖充分完整
- [ ] 文档更新及时准确

## 下一步

- 如果是小优化,继续迭代循环
- 如果是大版本升级,回到 `/story` 开始新周期
- 使用 `/handover` 生成交接 JSON
