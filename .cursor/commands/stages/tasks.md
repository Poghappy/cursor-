# 任务分解 (Task Breakdown)

**阶段目标**: 将 PRD 分解为可执行的技术任务。

## 输入来源

- **产品需求文档**: `docs/PRD.md`
- **技术设计文档**: `docs/TECH_DESIGN.md`（如果有）

## 输出要求

### 1. 任务分解原则

- **垂直切分**: 每个任务覆盖前后端全栈
- **独立交付**: 任务可独立测试和发布
- **合理粒度**: 1-3 天可完成
- **明确依赖**: 标识任务间依赖关系

### 2. 任务结构

每个任务包含：

```markdown
### TB-001: 任务标题

**优先级**: P0 (关键) / P1 (重要) / P2 (一般) **估时**: 2 人日 **依赖**: 无 或 TB-XXX

**功能描述**:

- 实现内容1
- 实现内容2

**技术要点**:

- 技术选型
- 关键实现

**验收标准**:

- [ ] 标准1
- [ ] 标准2
```

### 3. 任务分类

- **基础设施任务**: 项目初始化、环境搭建
- **功能开发任务**: 核心业务逻辑
- **测试任务**: 单元测试、集成测试
- **部署任务**: CI/CD、监控配置

### 4. 任务依赖图

使用 Mermaid 图表展示任务依赖关系

## 输出文件

生成 `docs/TASKS.md`，包含：

- 任务分解总览
- 详细任务列表
- 任务依赖图
- 开发计划

## 质量检查

- [ ] 任务粒度合理（1-3天）
- [ ] 任务独立可交付
- [ ] 依赖关系清晰
- [ ] 验收标准明确

## 下一步

完成后使用 `/handover` 生成交接 JSON，交接给 **Arch** 角色进行技术设计。
