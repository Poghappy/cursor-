# 测试阶段 (QA Test)

**阶段目标**: 验证实现的功能是否满足 PRD 中的验收标准。

## 输入来源

- **产品需求**: `docs/PRD.md`
- **实现代码**: `src/` 目录
- **现有测试**: `tests/` 目录

## 输出要求

### 1. 测试计划

- 测试范围和目标
- 测试策略（功能/性能/安全）
- 测试环境配置
- 测试数据准备

### 2. 测试用例

```markdown
| 用例ID | 功能     | 测试步骤                   | 预期结果 | 优先级 |
| ------ | -------- | -------------------------- | -------- | ------ |
| TC001  | 用户注册 | 1. 输入信息<br>2. 点击注册 | 注册成功 | 高     |
```

### 3. 测试执行

- **功能测试**: 验证所有功能需求
- **集成测试**: 验证模块间交互
- **性能测试**: 验证响应时间和吞吐量
- **安全测试**: SQL 注入、XSS、权限验证

### 4. 缺陷管理

```markdown
| 缺陷ID | 严重级别 | 描述     | 状态   |
| ------ | -------- | -------- | ------ |
| BUG001 | 严重     | 登录失败 | 已修复 |
```

### 5. 测试报告

- 测试执行结果
- 测试覆盖率统计
- 缺陷统计和分析
- 质量评估
- 发布建议

## 测试类型

### 功能测试

- 正常场景测试
- 异常场景测试
- 边界值测试
- 用户验收测试

### 性能测试

- 响应时间测试
- 并发用户测试
- 压力测试
- 负载测试

### 安全测试

- SQL 注入测试
- XSS 攻击测试
- 权限验证测试
- 数据加密测试

## 质量标准

- 测试用例覆盖率 > 90%
- 测试用例通过率 > 85%
- 缺陷发现率 > 95%
- 缺陷修复率 > 90%

## 输出文件

生成 `docs/TEST_REPORT.md`，包含：

- 测试计划
- 测试用例
- 测试结果
- 缺陷报告

## 质量检查

- [ ] 所有验收标准已验证
- [ ] 功能测试通过
- [ ] 性能测试达标
- [ ] 安全测试通过
