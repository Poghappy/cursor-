# 文件管理规范

**目标**：防止临时文件污染、文件散落、重复生成文档

---

## 📁 目录结构规范

### 正式文档目录

```
docs/
├── cursor/           # Cursor IDE 相关文档
├── product/          # 产品需求文档
├── project/          # 项目管理文档
├── technical/        # 技术设计文档
├── templates/        # 模板和参考文档
├── summaries/        # 阶段工作总结
├── examples/         # 示例代码和用法
└── archive/          # 归档文档
```

### 临时文件目录

```
tmp/
├── drafts/           # 草稿文档
├── generated/        # Agent 生成的临时文件
├── reports/          # 临时报告
└── backups/          # 临时备份
```

### 工作目录

```
.work/
├── analysis/         # 分析过程文件
├── planning/         # 规划过程文件
└── review/           # 审核过程文件
```

## 📝 文件命名规范

### 1. 正式文档命名

**格式**：`{TYPE}_{TOPIC}_{VERSION}.md`

**示例**：

- `PRD_USER_MANAGEMENT_v2.md` - 产品需求文档
- `TECH_AUTH_SYSTEM_v1.md` - 技术设计文档
- `GUIDE_QUICK_START_v3.md` - 使用指南

### 2. 临时文件命名

**格式**：`{DATE}_{TYPE}_{TOPIC}_temp.md`

**示例**：

- `20251002_ANALYSIS_USER_FLOW_temp.md` - 临时分析文档
- `20251002_DRAFT_API_DESIGN_temp.md` - 草稿文档
- `20251002_REPORT_PERFORMANCE_temp.md` - 临时报告

### 3. Agent 生成文件命名

**格式**：`{AGENT}_{DATE}_{TOPIC}_{STATUS}.md`

**示例**：

- `PO_20251002_PROJECT_BRIEF_draft.md` - PO 生成的草稿
- `ARCH_20251002_SYSTEM_DESIGN_review.md` - Arch 生成待审核文档
- `DEV_20251002_CODE_REVIEW_final.md` - Dev 生成的最终文档

## 🔄 文件生命周期

### 1. 创建阶段

**临时文件**：

- 所有新文件先创建在 `tmp/drafts/`
- 使用临时命名格式
- 添加状态标记：`[DRAFT]`、`[WIP]`、`[REVIEW]`

**检查点**：

- 文件名是否符合规范
- 是否存在重复内容
- 目录位置是否正确

### 2. 审核阶段

**流程**：

1. 从 `tmp/drafts/` 移动到 `tmp/review/`
2. 添加审核信息和版本号
3. 检查内容完整性和准确性

**标准**：

- 内容无重复
- 格式规范
- 信息完整

### 3. 发布阶段

**流程**：

1. 从 `tmp/review/` 移动到对应的 `docs/` 子目录
2. 更新文件名为正式格式
3. 更新相关索引文档

**检查**：

- 删除临时版本
- 更新 `docs/README.md` 索引
- 提交到 Git

### 4. 归档阶段

**条件**：

- 文档过时或被新版本替代
- 项目阶段结束

**流程**：

1. 移动到 `docs/archive/`
2. 添加归档时间和原因
3. 更新索引

## 🚫 防重复生成机制

### 1. 文件存在性检查

**规则**：

- 生成新文件前检查是否已存在相同主题文档
- 如存在，提示用户选择：更新现有文档 vs 创建新版本
- 新版本必须有明确的版本号和变更说明

### 2. 内容相似性检查

**机制**：

- 检查新文档与现有文档的相似度
- 相似度 > 80% 时警告可能重复
- 提供合并建议

### 3. 主题唯一性原则

**规则**：

- 每个具体主题只能有一个当前版本的正式文档
- 历史版本移动到 `archive/` 或添加版本后缀
- 维护主题到文档的映射表

## 🤖 Agent 行为规范

### 1. 文件生成规则

**必须遵循**：

- 所有 Agent 生成的文件先放在 `tmp/generated/`
- 使用标准的 Agent 文件命名格式
- 在文件头部添加生成信息：

```markdown
<!--
Generated by: {AGENT_ROLE}
Date: {YYYY-MM-DD HH:MM}
Topic: {TOPIC}
Status: {draft|review|final}
Related: {相关文档链接}
-->
```

### 2. 重复检查义务

**Agent 必须**：

- 生成文件前检查是否存在相同主题文档
- 如存在，说明差异和新增价值
- 提供合并或更新现有文档的建议

### 3. 文件转正流程

**步骤**：

1. Agent 生成文件到 `tmp/generated/`
2. 用户确认内容和位置
3. 运行 `make promote-file` 转为正式文档
4. 自动清理临时文件

## 🛠️ 自动化工具

### 1. 文件检查工具

**命令**：`make check-files`

**功能**：

- 检查文件命名规范
- 发现重复内容
- 验证目录结构
- 生成问题报告

### 2. 临时文件清理

**命令**：`make clean-temp`

**功能**：

- 清理超过 7 天的临时文件
- 备份重要临时文件
- 生成清理报告

### 3. 文档同步工具

**命令**：`make sync-docs`

**功能**：

- 更新文档索引
- 检查链接有效性
- 生成文档地图

### 4. 文件提升工具

**命令**：`make promote-file FILE=path/to/temp/file.md TARGET=docs/category/`

**功能**：

- 将临时文件转为正式文档
- 自动重命名和移动
- 更新索引

## ⚠️ 违规处理

### 常见违规

1. **临时文件提交到 Git**
   - 自动检测并警告
   - 提供清理命令

2. **重复文档生成**
   - 自动检测相似内容
   - 提示合并或版本控制

3. **文件命名不规范**
   - 自动检测并建议修正
   - 提供重命名工具

### 自动修复

```bash
# 检查并修复文件问题
make fix-files

# 清理违规文件
make clean-violations

# 重置文件结构
make reset-structure
```
