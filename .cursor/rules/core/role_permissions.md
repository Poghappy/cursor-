# 角色权限和约束规则

## 概述
本文件定义了 Cursor 多角色 Agent 团队中各个角色的权限范围、操作约束和安全规则，确保团队协作的安全性和有效性。

## 角色权限矩阵

### PO (Product Owner) 权限
**允许操作**:
- 创建和修改 `docs/PROJECT_BRIEF.md`
- 定义项目目标和范围
- 设置成功指标和约束
- 识别和评估风险
- 调用 `generate_project_brief` 函数

**禁止操作**:
- 直接修改技术实现代码
- 修改测试用例
- 修改部署配置
- 修改技术设计文档

**文件访问权限**:
- 读取: 所有文档文件
- 写入: `docs/PROJECT_BRIEF.md`
- 修改: 无
- 删除: 无

## 操作约束规则

### 文件修改约束
1. **单次修改限制**: 每个角色单次最多修改 {MAX_FILES} 个文件
2. **单文件行数限制**: 每个文件最多修改 {MAX_LINES} 行
3. **文件大小限制**: 单个文件大小不超过 1MB
4. **修改范围限制**: 只能修改角色权限范围内的文件

### 代码质量约束
1. **代码规范**: 所有代码必须通过 {LINT_CMD} 检查
2. **测试覆盖**: 所有代码必须有对应的测试用例
3. **测试通过**: 所有测试必须通过 {TEST_CMD} 检查
4. **覆盖率要求**: 代码覆盖率必须达到 80% 以上

### 安全约束
1. **敏感信息**: 禁止在代码中硬编码密码、密钥等敏感信息
2. **外部依赖**: 所有外部依赖必须通过适配层访问
3. **权限控制**: 严格按照角色权限矩阵执行操作
4. **数据保护**: 用户数据必须加密存储和传输

### 性能约束
1. **响应时间**: API 响应时间不超过 500ms
2. **内存使用**: 内存使用不超过 512MB
3. **CPU 使用**: CPU 使用率不超过 80%
4. **并发处理**: 支持至少 100 个并发用户

## 角色协作规则

### 信息传递规则
1. **交接格式**: 必须使用统一的交接 JSON 格式
2. **信息完整性**: 交接信息必须完整、准确、清晰
3. **时间要求**: 角色交接必须在 24 小时内完成
4. **确认机制**: 接收角色必须确认交接信息

### 冲突解决规则
1. **优先级**: 业务需求 > 技术实现 > 代码质量
2. **协商机制**: 冲突双方必须协商解决
3. **升级机制**: 无法解决的冲突升级到项目经理
4. **决策记录**: 所有冲突解决过程必须记录

### 质量保证规则
1. **代码审查**: 所有代码必须经过审查
2. **测试要求**: 所有功能必须经过测试
3. **文档更新**: 所有变更必须更新文档
4. **版本控制**: 所有变更必须提交到版本控制

## 安全规则

### 访问控制
1. **身份验证**: 所有角色必须通过身份验证
2. **权限验证**: 每次操作前必须验证权限
3. **操作审计**: 所有操作必须记录审计日志
4. **异常监控**: 异常操作必须立即告警

### 数据保护
1. **数据加密**: 敏感数据必须加密存储
2. **传输安全**: 数据传输必须使用 HTTPS
3. **备份策略**: 重要数据必须定期备份
4. **恢复机制**: 数据丢失时必须能够恢复

### 系统安全
1. **漏洞扫描**: 定期进行安全漏洞扫描
2. **依赖检查**: 定期检查依赖包的安全漏洞
3. **权限最小化**: 遵循最小权限原则
4. **安全更新**: 及时应用安全更新

## 监控和告警规则

### 性能监控
1. **响应时间**: 监控 API 响应时间
2. **资源使用**: 监控 CPU、内存、磁盘使用率
3. **错误率**: 监控系统错误率
4. **可用性**: 监控系统可用性

### 质量监控
1. **代码质量**: 监控代码质量指标
2. **测试覆盖**: 监控测试覆盖率
3. **文档完整性**: 监控文档完整性
4. **用户满意度**: 监控用户满意度

### 告警机制
1. **阈值告警**: 超过预设阈值时告警
2. **异常告警**: 检测到异常时告警
3. **故障告警**: 系统故障时告警
4. **安全告警**: 安全事件时告警

## 违规处理规则

### 违规类型
1. **权限违规**: 超出角色权限范围操作
2. **质量违规**: 代码质量不达标
3. **安全违规**: 违反安全规则
4. **流程违规**: 违反协作流程

### 处理措施
1. **警告**: 轻微违规给予警告
2. **暂停**: 严重违规暂停操作权限
3. **回滚**: 违规操作必须回滚
4. **培训**: 违规角色必须接受培训

### 申诉机制
1. **申诉渠道**: 提供申诉渠道
2. **申诉流程**: 明确的申诉流程
3. **申诉处理**: 及时处理申诉
4. **申诉结果**: 申诉结果必须记录

## 规则更新机制

### 更新触发
1. **定期更新**: 每季度更新一次
2. **问题驱动**: 发现问题时及时更新
3. **需求变更**: 业务需求变更时更新
4. **技术演进**: 技术栈演进时更新

### 更新流程
1. **需求收集**: 收集更新需求
2. **影响评估**: 评估更新影响
3. **规则制定**: 制定新规则
4. **规则评审**: 评审新规则
5. **规则发布**: 发布新规则
6. **规则培训**: 培训相关人员

### 版本控制
1. **版本号**: 使用语义化版本号
2. **变更记录**: 记录所有变更
3. **兼容性**: 确保向后兼容
4. **迁移指南**: 提供迁移指南
