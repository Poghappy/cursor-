# QA 测试阶段模板

## 阶段概述
作为资深 QA 工程师，请基于实现代码生成并执行质量测试，包括单元测试、集成测试、端到端测试，并输出测试报告和覆盖率分析。

## 输入参数
- **实现代码**: {implementation} (通常是 src/ 目录)
- **测试配置**: {test_config} (通常是 jest.config.js 或 package.json)
- **测试环境**: {test_env} (如 "development", "staging")
- **测试范围**: {test_scope} (如 "unit", "integration", "e2e")

## 输出要求

### 1. 测试计划
- 测试策略和范围
- 测试用例设计
- 测试环境配置
- 测试数据准备

### 2. 测试执行
- 单元测试执行
- 集成测试执行
- 端到端测试执行
- 性能测试执行

### 3. 测试报告
- 测试结果统计
- 失败用例分析
- 覆盖率报告
- 质量评估

### 4. 问题跟踪
- 缺陷列表
- 优先级分类
- 修复建议
- 回归测试计划

## 输出格式

### 测试计划
```markdown
## 测试计划

### 测试策略
- **单元测试**: 测试单个函数和类
- **集成测试**: 测试模块间交互
- **端到端测试**: 测试完整用户流程
- **性能测试**: 测试系统性能指标

### 测试范围
- 用户认证模块
- API 接口功能
- 数据库操作
- 错误处理机制

### 测试环境
- 开发环境: 本地 Docker 容器
- 测试环境: 独立的测试数据库
- 生产环境: 模拟生产环境配置

### 测试数据
- 有效用户数据
- 无效用户数据
- 边界值数据
- 异常数据
```

## 注意事项

### 测试原则
- **全面性**: 覆盖所有功能点
- **准确性**: 测试结果准确可靠
- **可重复性**: 测试可重复执行
- **及时性**: 及时发现问题

### 质量原则
- **零缺陷**: 关键功能零缺陷
- **高覆盖**: 代码覆盖率达标
- **快反馈**: 快速反馈问题
- **持续改进**: 持续优化质量

### 报告原则
- **客观性**: 客观反映测试结果
- **详细性**: 详细记录问题信息
- **可操作性**: 提供具体修复建议
- **可追踪性**: 问题可追踪管理
