# Guardrails - 安全与质量守则

## 安全约束

### 1. 敏感信息保护
- ❌ **禁止** 在代码中硬编码密钥、令牌、私钥
- ❌ **禁止** 将敏感信息提交到版本控制系统
- ✅ **必须** 使用环境变量或配置文件管理敏感信息
- ✅ **必须** 维护 `.env.example` 文件说明所需环境变量
- ✅ **必须** 在 README 中说明如何配置敏感信息

### 2. 数据安全
- ❌ **禁止** 在日志中输出敏感数据（密码、令牌、个人信息）
- ❌ **禁止** 在错误信息中泄露系统内部信息
- ✅ **必须** 对敏感数据进行脱敏处理
- ✅ **必须** 使用安全的密码哈希算法（bcrypt、scrypt）

## 代码质量约束

### 3. 改动规模限制
- 📏 **单回合最大文件数**: ≤ {MAX_FILES} 个文件（默认 5）
- 📏 **单文件最大改动行数**: ≤ {MAX_LINES} 行（默认 200）
- 📏 **必须展示文件树 Diff** 说明变更范围
- 📏 **超出限制时** 必须分解为多个小改动

### 4. 代码规范
- ✅ **必须** 遵循项目代码风格指南
- ✅ **必须** 添加必要的注释和文档
- ✅ **必须** 使用有意义的变量和函数名
- ❌ **禁止** 提交未使用的代码或注释掉的代码

## 外部依赖约束

### 5. 依赖管理
- ✅ **必须** 通过适配层封装外部依赖
- ✅ **必须** 为外部服务提供 Mock 实现
- ✅ **必须** 处理网络异常和权限异常
- ❌ **禁止** 直接调用外部 API 而不处理异常

### 6. 网络与权限
- 🔒 **网络异常**: 先 Mock，避免长链路副作用
- 🔒 **权限异常**: 提供降级方案
- 🔒 **服务不可用**: 实现熔断和重试机制

## 错误处理约束

### 7. 失败处理原则
- 📝 **日志记录**: 仅记录最短必要的错误信息
- 🔍 **根因分析**: 快速定位问题根本原因
- 🔧 **最小修复**: 实施最小化的修复方案
- ✅ **复测验证**: 修复后必须重新测试

### 8. 错误信息规范
```typescript
// ✅ 好的错误信息
throw new Error('User not found: userId=123');

// ❌ 避免的错误信息
throw new Error('Database connection failed at line 45 in UserService.ts');
```

## 可验证性约束

### 9. 质量门禁
- ✅ **必须** 通过 `{LINT_CMD}` 代码检查
- ✅ **必须** 通过 `{TEST_CMD}` 测试验证
- ✅ **必须** 通过 `{COVERAGE_CMD}` 覆盖率检查（如适用）
- ❌ **禁止** 在质量检查失败时进行交接

### 10. 测试要求
- 📊 **单元测试覆盖率**: ≥ 80%
- 🧪 **集成测试**: 关键路径必须覆盖
- 🔄 **端到端测试**: 主要用户流程必须验证
- 📝 **测试文档**: 测试用例必须有清晰的描述

## 交接约束

### 11. 交接格式
- 📋 **必须** 使用统一的 {HANDOFF_FORMAT} JSON 格式
- 📋 **必须** 包含变更计划摘要
- 📋 **必须** 说明影响面分析
- 📋 **必须** 提供文件树 Diff
- 📋 **必须** 明确 DoD（Definition of Done）

### 12. 流转条件
- ✅ **上游工件完整**: 所有依赖的文档和代码必须就绪
- ✅ **质量检查通过**: 所有自动化检查必须通过
- ✅ **文档同步更新**: 相关文档必须同步更新
- ❌ **禁止** 在条件不满足时强制流转

## 性能约束

### 13. 性能要求
- ⚡ **响应时间**: API 响应时间 < 2 秒
- ⚡ **并发处理**: 支持 100+ 并发用户
- ⚡ **资源使用**: 内存使用率 < 80%
- ⚡ **数据库查询**: 单次查询 < 1 秒

### 14. 性能优化
- 🚀 **数据库优化**: 合理使用索引，避免 N+1 查询
- 🚀 **缓存策略**: 合理使用缓存减少数据库压力
- 🚀 **异步处理**: 耗时操作使用异步处理
- 🚀 **资源压缩**: 静态资源必须压缩

## 安全约束

### 15. 输入验证
- 🔐 **所有输入必须验证**: 长度、格式、类型
- 🔐 **防止注入攻击**: SQL 注入、XSS、CSRF
- 🔐 **参数化查询**: 数据库查询必须使用参数化
- 🔐 **输出编码**: 所有输出必须正确编码

### 16. 认证授权
- 🔑 **强密码策略**: 密码复杂度要求
- 🔑 **会话管理**: 安全的会话管理机制
- 🔑 **权限控制**: 基于角色的访问控制
- 🔑 **令牌安全**: JWT 令牌安全使用

## 监控约束

### 17. 日志规范
- 📊 **日志级别**: ERROR、WARN、INFO、DEBUG
- 📊 **结构化日志**: 使用 JSON 格式
- 📊 **敏感信息**: 不得记录敏感信息
- 📊 **日志轮转**: 配置日志轮转策略

### 18. 监控指标
- 📈 **业务指标**: 用户数、功能使用率
- 📈 **技术指标**: 响应时间、错误率、吞吐量
- 📈 **系统指标**: CPU、内存、磁盘使用率
- 📈 **告警机制**: 关键指标异常时及时告警

## 紧急情况处理

### 生产环境问题
1. **立即响应**: 5 分钟内响应
2. **快速定位**: 使用监控和日志快速定位
3. **最小修复**: 实施最小化修复
4. **回滚准备**: 必要时立即回滚
5. **事后分析**: 问题解决后进行根因分析

### 安全事件
1. **立即隔离**: 隔离受影响的系统
2. **评估影响**: 评估安全事件的影响范围
3. **修复漏洞**: 修复安全漏洞
4. **通知相关方**: 通知相关利益相关者
5. **改进防护**: 改进安全防护措施
